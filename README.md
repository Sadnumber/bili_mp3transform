# bili_mp3transform

将 B 站客户端下载的 m4s 缓存文件解密并转换为可播放的 **MP3 音频** 或 **带声音的完整 MP4 视频**。

提供开箱即用的 Windows 图形界面程序（单文件 exe，内置 Python 运行时与 ffmpeg，**无需安装任何环境**），同时保留原有的命令行脚本。

## 一、图形界面（推荐）

### 获取程序
打包后的 `dist/B站缓存转换器.exe` 为单文件绿色程序，约 38 MB，可直接拷贝到任意 Windows 10 / 11 (x64) 电脑运行。

### 使用步骤
1. 双击 `B站缓存转换器.exe`，打开后界面如上图所示，分为三个区域：

   **设置区（顶部）**
   | 设置项 | 说明 | 默认值 |
   | --- | --- | --- |
   | B站缓存目录 | B 站客户端「设置 → 下载设置」中的缓存路径（必填） | 自动猜测 |
   | 输出目录 | 转换后的文件存放位置 | 桌面「B站转换输出」文件夹 |
   | MP3 码率 | 音频模式下的输出码率 | 192k |
   | 完成后删除中间文件 | 勾选后只保留最终的 mp3 / mp4 | 未勾选 |
   | 完成后打开输出目录 | 勾选后自动打开资源管理器 | 已勾选 |

2. 首次使用时填写或浏览选择 **B站缓存目录**（必填项带 `*` 标记），其余可保持默认。程序会自动尝试猜测常见的缓存路径（如 `D:\用户名\Videos\bilibili`）。
3. 点击下方两个大按钮之一即可开始转换：
   - **转换为音频 (MP3)** —— 提取每个视频的音频流并重编码为 MP3 文件。
   - **转换为完整视频 (MP4)** —— 将音视频流合并为带声音的完整 MP4（仅封装不重编码，无损且快速）。
4. 转换过程中可在下方 **日志面板** 实时查看进度（扫描数量、正在处理的文件、ffmpeg 路径等）；
   右侧 **停止** 按钮可随时中断当前任务。底部状态栏显示当前进度（如 `已完成`、`1/5` 等）。

所有设置会自动保存到 `%APPDATA%\BiliCacheConverter\config.json`，下次打开无需重复配置。

> **注意**：程序不会修改原始缓存——处理前会先把缓存文件复制到输出目录再操作，安全无副作用。

## 二、自行打包 exe

环境要求：Windows + Python 3.8 及以上。

```bash
python build.py
```

脚本会自动完成：
1. 安装 PyInstaller（若未安装）。
2. 下载精简版 ffmpeg 到 `bin/ffmpeg.exe`（已存在则复用）。
3. 调用 PyInstaller 打包为单文件 exe，输出到 `dist/`。

可选参数：

| 参数 | 说明 |
| --- | --- |
| `--ffmpeg <路径>` | 使用本机已有的 ffmpeg.exe，跳过下载 |
| `--onedir` | 打包为目录而非单文件（启动更快，体积略大） |

若网络受限导致下载失败，可手动下载 ffmpeg 并将 `ffmpeg.exe` 放到项目的 `bin/` 目录后再运行 `python build.py`。

## 三、工作原理

- B 站的“加密”很简单：在 m4s 文件开头放入 9 个 `0` 字节，删除即可还原为标准 MP4 容器。
- 每个缓存文件夹内有两个 m4s：一个音频流（AAC 编码），一个视频流（H.264 / HEVC / AV1 编码）。
- **图形界面版的音视频流识别规则**：
  - **音频流**：默认取文件名含 `-30280` 的文件；找不到时，取文件夹内**体积更小**的 m4s（更大者大概率是视频）。
  - **视频流**：默认取文件名含 `-30080` 或 `-100050` 的文件；找不到时，取文件夹内**体积更大**的 m4s。
  - B 站不同清晰度编号不固定（音频有 `30216` / `30232` / `30250` 杜比等，视频有 AV1 的 `100xx` 等），
    因此默认编号找不到时一律回退到体积大小判断。
  - 最后还会用 ffmpeg 探测每个流的**实际轨道类型**来校正结果——编号和体积都只是猜测，
    探测到的 Video / Audio 轨道才是事实依据，确保任何命名和体积情况下都不会选错。
- 视频标题读取自缓存目录中的 `videoInfo.json`，并兼容旧版客户端的 `entry.json`。

## 四、文件说明

| 文件 | 说明 |
| --- | --- |
| `app.py` | 图形界面主程序（tkinter，无第三方依赖） |
| `core.py` | 核心逻辑：ffmpeg 定位、缓存扫描、解密、转 MP3、合并 MP4 |
| `build.py` | 一键打包脚本 |
| `utils.py` | 旧版命令行脚本共用的工具函数 |
| `main.py` | 命令行：从缓存目录筛选 m4s 并按标题归类到 `output/` |
| `sound.py` | 命令行：将音频 m4s（`-30280`）解密为 `.m4a` |
| `video.py` | 命令行：将 m4s 音视频流解密并合并为带音频的完整 mp4 |
| `to_mp3.py` | 命令行：将 `.m4a` 用 ffmpeg 重编码为 `.mp3` |

## 五、命令行用法（旧流程）

所有脚本的目标目录默认值均为项目内的 `output/` 文件夹。

```bash
python main.py -s /path/to/bilibili_cache   # 提取并按标题归类
python sound.py                             # 音频 m4s -> m4a
python video.py                             # 视频 m4s -> mp4
python to_mp3.py                            # m4a -> mp3（-b 指定码率）
python video.py                             # m4s -> 带音频的完整 mp4
```

主要参数：

- `main.py`：`-s` 缓存目录（必填）、`-t` 目标目录、`-p` 文件名匹配模式
- `sound.py` / `video.py`：`-i` 输入目录、`-o` 输出根目录、`--clean` 清理中间文件
- `to_mp3.py`：`-i` 输入目录、`-b` 码率（默认 `192k`）

> 命令行流程依赖系统已安装 `ffmpeg`；图形界面版本已内置 ffmpeg，无此要求。
